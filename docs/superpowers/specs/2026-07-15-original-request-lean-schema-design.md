# 原版请求结构与精简输出设计

## 目标

在不更换模型、不分批、不降低日报完整性的前提下，恢复原版有效的消息布局，移除新版中模型不需要回显的链接和来源，避免完整 JSON 在结尾被挤掉。

## 已验证事实

- 原版将整批资讯插入系统提示，用户消息仅要求处理当天条目。
- 新版将整批资讯放入用户消息，并携带 25 条真实链接。
- 新版最终强制使用本地抓取的链接、来源和分类，不使用模型返回的 link 或 source。
- 2026-07-15 的 25 条链接共 1,425 个字符；当前完整请求在 HTTP 200 后返回未闭合 JSON，被严格校验正确拒绝。

## 设计

1. 系统消息包含提示词和当天完整资讯，用户消息恢复为简短处理指令。
2. 模型 JSON 只包含 todayObservation、每条 title 与 rewritten、以及 editorComment。
3. 程序继续将本地抓取的链接、来源和分类附回每一条改写结果。
4. 解析时可接受完整 JSON 代码块；缺少 JSON 结尾、缺条、缺今日观察或缺小编短评仍然失败。
5. 保留现有同批资讯 AI 格式重试一次，以及正式定时任务两次失败后的 Windows 提示。

## 非目标

- 不恢复原版的原始资讯兜底文章。
- 不减少当天条数、不拆分 AI 请求、不修改模型或凭证。
- 不改变文章排版、今日观察、小编短评、封面或微信发布逻辑。
