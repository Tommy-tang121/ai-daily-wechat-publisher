# 定时日报失败通知设计

**状态：** 已实施，2026-07-22 已同步网络重试节奏。

## 目标

每天的正式定时任务只有两次完整处理机会：首次执行和重试一次。AIHot 资讯源连接或 DNS 解析失败时，两次之间等待 60 秒；其他允许重试的发布前失败直接进入第二次。两次后仍未确认微信草稿箱已创建，就在 Windows 桌面弹出失败原因；不再依赖五分钟后的检查任务。

## 范围

- 覆盖抓取、AI 连接、AI 返回格式、排版、封面和发布流程的失败。
- 保留单次整篇 AI 改写；AI 格式错误仍使用同一批当天资讯重试一次。
- 删除任务计划程序的十五分钟失败重启，避免总次数超过两次。
- 弹窗仅来自正式 `ai-daily daily` 定时任务，网页手动预览不弹窗。
- 60 秒等待只用于 AIHot 抓取抛出的 `requests.ConnectionError`，不增加重试次数，也不延迟微信结果待确认的提示。

## 成功判定

- `published` 或 `finalizing` 表示微信草稿已成功创建，不弹窗。
- 首次 AIHot 连接失败时等待 60 秒再执行第二次完整处理；其他允许重试的预发布失败立即执行第二次。
- 第二次预发布阶段失败时，只弹一次 Windows 提示，显示经过长度限制和敏感值脱敏后的原因。
- AIHot 域名解析失败时，弹窗显示“资讯源域名解析失败，请检查网络、VPN 或 DNS”。

## 微信发布的安全边界

微信发布请求出现网络错误或无回包时，系统无法判断微信是否已创建草稿。此时状态为 `publication_uncertain`，不得再次调用微信发布接口，否则可能生成重复草稿。

该状态会立即弹窗，明确说明“发布结果待确认，请检查草稿箱”，而不会错误地宣称草稿一定未创建。它不进入第二次微信发布。

## 非目标

- 不恢复或新增五分钟 Hook / 检查任务。
- 不保存资讯正文、模型原始返回或密钥到数据库、日志或弹窗。
- 不改变网页端的交互和文章格式。
- 不增加第三次尝试或任务计划程序级别的失败重启。
