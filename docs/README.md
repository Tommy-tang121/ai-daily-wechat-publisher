# AI Daily

本地运行的 AI 日报编辑与微信公众号草稿工具。它抓取当天全部可用资讯，用一次模型请求同时生成“今日观察”、全部改写正文和“小编短评”，再生成封面；只有收到微信草稿回执后，才会标为已发布。

## 日常使用

1. 双击 `app/scripts/run_preview.bat` 做生成、预览和封面测试。预览模式禁止创建微信草稿。
2. 双击 `app/scripts/run_web.bat` 打开正式 Web 页面。
3. 在页面选择日期，点击“抓取”。系统会把当天全部资讯一次发送给模型，并在同一份 JSON 中取得开篇、全部条目和结尾；返回条目数必须与抓取数完全一致，否则本次生成失败，不会悄悄漏新闻。处理中的运行、已生成未发布的文章和调用微信草稿接口前失败的可重试内容会临时保留，刷新或重新打开后可继续查看。微信调用后结果未知时，页面只显示“发布结果待确认”，不会重试或显示旧正文。
4. 文章状态显示“已生成，尚未发布”时，可预览、复制或查看封面；确认后再点击“发布”。
5. 设置每日时间并点击“保存”，会更新唯一的 Windows 任务 `AI Daily Publisher`。正式任务最多执行两次完整流程：首次失败后立即重试一次；两次仍未确认微信草稿已创建时，Windows 会弹出脱敏后的失败原因。

## 首次安装

在项目根目录运行：

```powershell
py -m pip install --user uv
py -m uv sync --project app --locked
```

在项目根目录创建本机 `.env`，填写 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`。当前已验证的 DeepSeek 配置为 `https://api.deepseek.com` 与 `deepseek-v4-flash`；日报请求会关闭思考模式并要求 JSON 返回。密钥不进入 Git，也不写入日志。

还需要安装 Bun，供已复用的微信草稿发布器运行。

## 运行边界

- 不需要服务器；Windows 电脑必须开机且当前用户保持登录，计划任务才能执行。
- 微信 IP 白名单仍需每天由你手动更新；这是当前明确保留的人工步骤。
- 本地只暂存处理中的运行、`ready` 文章和尚未调用微信草稿接口前失败的可重试内容。微信草稿创建成功后，会立即清除本地文章、事件、封面和运行记录；不保留已发布历史或草稿回执。
- 手动选择任意日期点击“抓取”会开始一次新的生成；同一天已完成或失败的旧内容不会被复用。
- 单次模型请求没有“25 条”这一固定截断阈值。是否可完成取决于当天原文总量和模型服务的输入、输出上限；系统只接受完整 JSON 和与抓取数相同的条目数，模型截断或少返回时会明确失败而不会生成残缺草稿。
- 抓取和改写每次上报有效进度都会刷新运行心跳；只有连续超过 30 分钟没有进度的排队、抓取或改写任务，才允许定时重试接管。`publishing` 即使过期也绝不接管或重发，而是在下次状态检查时转为“发布结果待确认”。若定时任务发现一个仍健康、自己并不拥有的排队或处理中任务，会以失败退出；正式任务仅在其最多两次完整处理机会内重试，不会再创建额外的 15 分钟检查任务。清理开始后，旧线程再上报进度会被忽略，页面也不会显示旧事件。
- 定时任务按运行日期生成标题。调用微信草稿发布器前的生成失败可以重试；一旦开始调用发布器，任何异常都视为远端结果未知，必须先在微信草稿箱核对并由你确认，系统绝不自动再次发布。
- 本地设置和保存的计划时间会继续保留；草稿成功后的运行清理不会改动它们。
