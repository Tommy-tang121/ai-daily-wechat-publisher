# AI Daily 旧版草稿格式恢复规格

## 目标

恢复旧版微信公众号草稿的正文结构、来源呈现、封面视觉和发布参数，同时保留“抓取当天全部资讯、一次完整改写”的稳定性能力。

## 不在范围内

- 不接入 `baoyu-format-markdown`。
- 不修改已创建或已发布的微信公众号草稿。
- 不改变资讯抓取来源、日期任务、发布权限或现有配置文件。

## 正文契约

每篇新生成文章必须按下列顺序输出：

1. `今日观察`：基于当天全部改写完成的资讯生成。
2. 按资讯分类分组；每个分类使用 `【分类名】` 标题。
3. 每条资讯依次显示标题、正文、`来源：来源名`。
4. `小编短评`：与今日观察围绕同一条主线，但不重复内容。
5. `数据来源：https://aihot.virxact.com/`。

文章排版沿用旧版的中文标点和连续空行整理规则。来源链接仍在内部文章数据中保留，供追溯使用，但不以 Markdown 链接和文末自动引文改变旧版草稿视觉。

## 生成流程

当天全部资讯在一次模型请求中处理；该请求同时生成“今日观察”、全部条目改写和“小编短评”。返回 `items` 的数量必须与抓取数完全一致，条目不能遗漏、合并或新增。

若这次请求的 JSON 无效、缺任一栏目或少返回条目，整次生成失败，不得生成不完整草稿。

## 封面契约

封面恢复旧版 900×500 手帐风样式：渐变纸张底色、圆角墨色边框、双顶线、`AI Daily` 刊头、居中主标题、红色日期及波浪线、星期和作者署名。标题与日期分别绘制，不能将“标题 | 日期”拼成一行。

## 发布契约

继续使用现有 `baoyu-post-to-wechat` 发布器和默认主题，但必须传入 `--no-cite`，关闭外链自动文末引文。

## 验收

- 生成 11 条以上（含 25 条）资讯时，文章仍包含全部条目并保留上述五段结构，且只调用模型一次。
- 缺少今日观察、小编短评、分类标题或数据来源时，自动测试失败。
- 以固定日期、标题和作者生成的封面与旧版基准封面像素一致。
- 发布命令包含 `--no-cite`。
- 全部既有 Python 测试、发布器测试和本次新增测试通过。
