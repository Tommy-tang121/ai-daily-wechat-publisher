# AI Daily 模型输出合约

> 同步日期：2026-08-04
>
> 本文件补充当前有效的运行规格；若与旧计划文件冲突，以本文件和实际代码为准。

## 要解决的问题

模型有时会漏掉资讯、调换输出顺序、重复某条内容，或在输出到一半时结束。只检查“返回了几条”不能防止来源链接被错配到另一条资讯。

## 当前规则

1. 系统为当天每条输入资讯分配从 1 开始的连续 `id`，并把编号、标题、摘要和来源一同交给模型。
2. 模型必须在每个 `items` 条目中原样返回 `id`、`title` 和 `rewritten`；同时返回非空的 `todayObservation` 和 `editorComment`。
3. 系统只接受 JSON 对象和数组形式的 `items`。非文本响应、无法解析的 JSON、缺少必填字段、缺失/重复/未知编号、空标题或空正文都会被拒绝。
4. 系统按 `id` 重新排序模型返回的条目，再与原始资讯匹配来源链接；不依赖模型返回的先后顺序。
5. 第一次失败后，第二次请求会带上具体失败原因，要求模型完整重做。第二次仍失败时，整次运行失败，不生成残缺文章，也不会创建微信草稿。

## 诊断和安全边界

- 日志只保存失败原因、模型结束原因、响应字符数、输入 token 数和输出 token 数。
- 不保存模型正文、API Key、微信公众号 AppID 或 AppSecret。
- 当模型因长度上限结束时，最终失败提示会说明“模型输出达到长度上限”，便于判断是否需要减少当天输入量或调整模型额度。

## 用户可见结果

页面沿用原有的“重写中 → 完成 / 失败”状态。编号校验没有新增页面按钮或视觉组件；校验失败会进入既有错误状态，首次失败后自动重试一次。
